# Касса — учёт овощного магазина

Веб-приложение для телефона: закупки (приход товара), касса (наличные и терминал отдельно), расходы, списания, долги покупателей, итоги дня и месяца. Валюта — гривна, часовой пояс — Киев.

- **Сайт:** Next.js + TypeScript + Tailwind, хостинг Vercel.
- **База и вход:** Supabase (Postgres + вход по почте и паролю). Права проверяет сама база: продавец **не видит** закупочные цены и заработок, даже если обратится к базе напрямую.
- **Телефон:** ставится на рабочий стол как приложение (PWA).

## Запуск (делается один раз)

Всё бесплатно. Займёт около 20 минут. Если какая-то кнопка называется немного иначе, чем здесь написано, сделайте скриншот и пришлите его мне.

### Шаг 1. Supabase: база данных

1. Откройте **https://supabase.com** → **Start your project** → **Continue with GitHub** и войдите своим GitHub.
2. Нажмите **New project**.
   - **Name:** `kassa`.
   - **Database Password:** нажмите **Generate a password** и **сохраните пароль** в заметках телефона. Он понадобится редко, но восстановить его сложно.
   - **Region:** ближайший к Украине, например **Central EU (Frankfurt)**.
   - Нажмите **Create new project** и подождите 1–2 минуты.
3. Слева откройте **SQL Editor**, затем **New query**.
4. Откройте в GitHub файл [`supabase/migrations/20261104000001_init.sql`](supabase/migrations/20261104000001_init.sql), нажмите кнопку **Copy raw file** (значок копирования справа над текстом), вставьте текст в окно SQL Editor и нажмите **Run**.
   Внизу должно появиться **Success. No rows returned**. Если вместо этого красная ошибка, пришлите мне её скриншот.
5. Запретите посторонним регистрироваться: слева **Authentication** → **Sign In / Providers** (или **Settings**) → выключите **Allow new users to sign up** → **Save**.
6. Создайте свой вход: **Authentication** → **Users** → **Add user** → **Create new user**.
   - Введите почту и пароль, которыми будете входить в приложение.
   - Поставьте галочку **Auto Confirm User** → **Create user**.
7. Возьмите два ключа для шага 2: нажмите вверху кнопку **Connect** (или слева **Project Settings** → **API Keys**). Скопируйте в заметки:
   - **Project URL**: строка вида `https://abcdefgh.supabase.co`;
   - **Publishable key**: начинается с `sb_publishable_…`. Если такого нет, подойдёт ключ **anon public**.

   ⚠️ Ключ **service_role / secret** никуда не копируйте и никому не отправляйте: он даёт полный доступ к базе.

### Шаг 2. Vercel: сайт по вашей ссылке

1. Откройте **https://vercel.com** → **Sign Up** → тариф **Hobby** → **Continue with GitHub**.
2. **Add New…** → **Project**. В списке найдите репозиторий **`-`** и нажмите **Import**.
   Если репозитория нет в списке, нажмите **Adjust GitHub App Permissions** и разрешите Vercel доступ к нему.
3. Перед нажатием **Deploy** раскройте **Environment Variables** и добавьте две строки:

   | Key (имя) | Value (значение) |
   |---|---|
   | `NEXT_PUBLIC_SUPABASE_URL` | Project URL из шага 1.7 |
   | `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | Publishable key из шага 1.7 |

4. Нажмите **Deploy** и подождите 1–2 минуты. Vercel покажет ссылку вида `https://….vercel.app`. Это адрес вашего приложения.

### Шаг 3. Телефон

1. Откройте ссылку в **Chrome** на Android и войдите почтой и паролем из шага 1.6.
2. При первом входе приложение предложит создать магазин: введите название и нажмите **Создать магазин**.
3. Меню Chrome **⋮** → **Установить приложение** (или **Добавить на главный экран**). На рабочем столе появится иконка «Касса».

## Как обновляется приложение

- Каждое изменение кода в GitHub Vercel сам собирает и выкладывает за 1–2 минуты. Ничего нажимать не нужно.
- Если меняется база данных, в папке `supabase/migrations/` появится новый файл. Его нужно один раз выполнить в **SQL Editor**, как в шаге 1.4. О каждом таком файле я предупреждаю отдельно. Файлы выполняются **по порядку**, каждый **один раз**.

## Где что лежит

```
src/app/              экраны
src/components/       общие части интерфейса, вход
src/lib/money.ts      все расчёты денег (копейки, округление, наценка, сверка кассы)
src/lib/dates.ts      даты по Киеву
supabase/migrations/  схема базы, права доступа, итоги
supabase/seed/        ваши данные за 1–4 ноября 2026 (для импорта)
supabase/tests/       проверки прав и итогов на тестовой базе
tests/                проверки расчётов, включая контрольные итоги из Excel
public/sw.js          работа без интернета
```

## Правила расчётов

- Деньги хранятся в **копейках** (целые числа), количество — с точностью до 0,001.
- Сумма строки = количество × цена, округление до копейки (половина вверх). Итог дня — сумма строк, итог месяца — сумма дней. Поэтому всё совпадает до копейки.
- **Заработок дня** = приход − закупка. Расходы и списания показываются отдельно и из заработка дня не вычитаются.
- Закупку можно ввести **ценой за кг** или **общей суммой**, отданной поставщику. Во втором случае цена за кг считается сама, а сумма сохраняется ровно такой, какую отдали.
- **Цена продажи по наценке** округляется вверх до 1 ₴ (шаг можно поменять в настройках магазина).
- **Касса дня:**
  - выручка наличными = наличные вечером − наличные утром − снял с карты + отдано поставщикам из кассы + расходы из кассы + забрал себе;
  - выручка всего = выручка наличными + терминал;
  - сверка = выручка всего − (приход − продано в долг + возвращённые долги).
- **Удаление** переносит запись в корзину. Через 30 дней она стирается окончательно.

## Роли

| Роль | Что может |
|---|---|
| Владелец (owner) | всё |
| Продавец (seller) | вносить закупки, кассу, расходы, списания, долги. **Не видит** цены и суммы закупки, заработок и суммы списаний |
| Наблюдатель (viewer) | смотреть всё, ничего не менять (бухгалтер) |

## Для разработчика

```bash
npm install
cp .env.example .env.local   # вписать URL и publishable key
npm run dev                  # http://localhost:3000
npm test                     # расчёты и контрольные итоги
npm run lint && npm run typecheck
PGURL=postgres://postgres@localhost:5432/postgres scripts/test-db.sh   # миграции и права на локальном Postgres
```
